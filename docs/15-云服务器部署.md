# 云服务器部署（阿里云 ECS / Ubuntu）

> 本文回答：**云上也能按本地那套操作跑起来吗？**
> 答案：**能跑，但不能照搬。** 云上和本地有 6 处本质差异，而且你这台 ECS 上还卡着 **2 个硬阻塞**。
>
> 配套脚本：`scripts/setup_cloud.sh`（云上专用，幂等，可反复跑）
> 相关文档：`docs/14-拉取代码后如何跑起来.md`（本地/新人上手）、`docs/13-项目完整介绍与操作手册.md`

## 3. 本地 vs 云上：6 处本质差异

| # | 维度 | 本地（macOS） | 云上（你的 ECS） | 影响 |
| --- | --- | --- | --- | --- |
| 1 | **PG 怎么来** | `docker run postgres:16`，或 SSH 隧道连云上 | **原生安装 + 已在跑**，`127.0.0.1:5432` | 云上**不需要 Docker、不需要隧道**；反而要小心别重复起一个 |
| 2 | **向量库** | `data/milvus.db`（本地） | `/opt/rag-agent/data/milvus.db` | 路径由 `BASE_DIR` 决定，见 §10 |
| 3 | **Python 版本** | 3.13 | **3.10.12** | 依赖要选兼容 3.10 的版本；本项目实测 3.10 可用 |
| 4 | **torch 版本** | 大多默认 CUDA 版 | **已装 `+cpu` 版** | 云上这块已经有人处理好了，别重装成 CUDA 版 |
| 5 | **前端能不能跑** | Node 22 有，`npm run dev` | **没装 Node** | 要么装 Node，要么本地 build 后传 `dist/` |
| 6 | **访问方式** | 浏览器直连 `127.0.0.1` | 必须**监听 `0.0.0.0`** + **开安全组** | 否则服务起来了但外面访问不到 |

还有一个**隐性差异**，是最容易踩的（见 §10）：`core/config.py` 里有一行「若 `/opt/rag-agent` 存在就用它当 BASE_DIR」，
所以云上 `BASE_DIR` 会自动变成 `/opt/rag-agent`，而**不是**你 clone 代码的那个目录。

## 4. 云上的 2 个硬阻塞

### 阻塞 ①：云上 venv 缺 `fastapi` / `uvicorn`

实测：

```
/opt/rag-agent/venv/bin/python -c "import fastapi"
→ ModuleNotFoundError: No module named 'fastapi'
```

云上现有 venv 只装了「入库 / 检索」这条链路要用的包（torch、pymilvus、sentence-transformers…），
**没装「HTTP 服务」这条链路要的包**。所以 `scripts/api.py`（前端要打的后端）在云上根本起不来。

**解决**：装 3 个纯 Python 包（很小，几秒）：

```bash
/opt/rag-agent/venv/bin/pip install fastapi uvicorn python-multipart \
  -i https://pypi.tuna.tsinghua.edu.cn/simple/
```

> `python-multipart` 少不得——上传接口用 `UploadFile`/`Form`，缺了 FastAPI 会在启动时报
> `Form data requires "python-multipart" to be installed`。

**云上实测缺的包完整清单**（用 `importlib.util.find_spec` 逐个探过）：

| 包 | 必要性 | 说明 |
| --- | --- | --- |
| `fastapi` | ★ **必需** | 起 API 的核心 |
| `uvicorn` | ★ **必需** | ASGI 服务器 |
| `python-multipart` | ★ **必需** | `UploadFile`/`Form`（上传接口） |
| `pdfplumber` | 可选 | 上传 **PDF** 才需要；前端 accept 里有 `.pdf`，不装则上传 PDF 报错 |
| `python-docx` | 可选 | 上传 **DOCX** 才需要，同上 |
| `streamlit` | 可选 | 只有跑老 UI（`scripts/ui.py`）才需要 |

`scripts/setup_cloud.sh` 默认把上面 4 个（含两个可选）都补上；用 `SKIP_EXTRAS=1` 可跳过可选的两个（省约 15MB）。
云上**已经有**的不重复装：`torch 2.9.1+cpu`、`transformers`、`sentence-transformers`、`pymilvus`、`milvus-lite`、`psycopg2-binary`、`numpy`、`python-dotenv`。

### 阻塞 ②：云上 `.env` 没有 LLM 配置 ← **这个更隐蔽**

云上 `.env` 实测只有这些键：`PG_*`、`MILVUS_*`、`MODEL_ROOT`、`EMBED_*`、`RAG_BASE_DIR`、`RAG_CORPUS_DIR`。
**一个 `LLM_*` / `OPENAI_*` 都没有**。于是 `LLM_BACKEND` 走代码默认值 `openai`，而 `OPENAI_API_KEY` 空：

```
/opt/rag-agent/venv/bin/python -c "import sys;sys.path.insert(0,'.');from core import config;print(config.validate())"
→ ['LLM_BACKEND=openai 时需要设置 OPENAI_API_KEY']
```

关键在于 `scripts/api.py` 的 `lifespan` 里做了 **fail-fast**：

```python
errs = config.validate()
if errs:
    raise RuntimeError("配置校验失败: " + "; ".join(errs))
```

所以**服务不是"问答时报错"，而是启动就退出**。这就是为什么云上一直没跑起来。

**解决**：把本地 `.env` 里那 4 行补到 `/opt/rag-agent/app/.env`（值要和本地一致）：

```ini
LLM_BACKEND=openai
LLM_MODEL=qwen3.7-max
OPENAI_API_KEY=sk-你的key
OPENAI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

然后确认：

```bash
cd /opt/rag-agent/app && /opt/rag-agent/venv/bin/python -c \
  "import sys;sys.path.insert(0,'.');from core import config;print(config.validate() or '[] 通过')"
```

## 5. 一键脚本（推荐）

```bash
# 在云上（bash scripts/setup_cloud.sh 会自动检测 /opt/rag-agent）
bash scripts/setup_cloud.sh
```

它做的事（**幂等**，可反复跑）：

| 步 | 内容 |
| --- | --- |
| [1/5] | 环境体检：Python / venv / PostgreSQL / 端口 / 磁盘 / 内存 |
| [2/5] | **只补缺的** Python 依赖（云上实测缺 6 个：fastapi / uvicorn / python-multipart + pdfplumber / python-docx） |
| [3/5] | 校验 `.env`；缺 LLM 配置时给出**明确的修复指引**并退出（不让你带着坏配置启动） |
| [4/5] | 校验数据：语料篇数 / 模型目录 / 向量库 / PG 里的 document 与 chunk 数 |
| [5/5] | 前端（**可选**，`FRONTEND=1`）：装 Node + `npm run build` |
| 附加 | `SYSTEMD=1` 时额外写 `/etc/systemd/system/rag-agent-api.service` |

可用参数：

```bash
FRONTEND=1 bash scripts/setup_cloud.sh     # 顺带装 Node + 构建前端
SYSTEMD=1  bash scripts/setup_cloud.sh     # 顺便写 systemd 常驻服务
SKIP_APT=1 bash scripts/setup_cloud.sh     # 不用 apt 装系统包
SKIP_EXTRAS=1 bash scripts/setup_cloud.sh  # 不装 pdfplumber / python-docx
RAG_APP_DIR=/opt/rag-agent bash scripts/setup_cloud.sh
API_PORT=8080 FE_PORT=8081 bash scripts/setup_cloud.sh
NODE_MAJOR=22 FRONTEND=1 bash scripts/setup_cloud.sh
```

> **本地的 `setup_new_machine.sh` 已被加了保护**：检测到 `/opt/rag-agent` 就会拒绝执行并提示改用本脚本
> （避免在云上白建一个 venv、重下 183MB 模型、还想用不存在的 Docker 起 PG）。

## 7. ★ 让浏览器能访问（最容易漏的一步）

`scripts/api.py` 默认监听 `127.0.0.1`（**只有服务器自己能访问**）。云上必须：

### 7.1 服务改监听 `0.0.0.0`

```bash
/opt/rag-agent/venv/bin/python scripts/api.py --host 0.0.0.0 --port 8000
```

### 7.2 阿里云控制台开安全组

**ECS 控制台 → 安全组 → 配置规则 → 入方向 → 手动添加**：

| 协议 | 端口 | 授权对象 | 用途 |
| --- | --- | --- | --- |
| TCP | 8000 | 你的公网 IP（**别写 0.0.0.0/0**） | 后端 API / Swagger |
| TCP | 5173 | 你的公网 IP | 前端（仅 demo 用） |

> **安全建议**：
> - 授权对象尽量填**自己家里的公网 IP**，而不是 `0.0.0.0/0`——这个服务**没有登录鉴权**，
>   对全网开放等于把知识库和 LLM key 的调用能力公开了。
> - 正式部署更推荐：只放行 80/443，用 **nginx 反代**到 `127.0.0.1:8000`（见 §9），
>   这样后端端口根本不用对外暴露。
> - 如果你只是自己临时看效果，更稳的做法是用 **SSH 端口转发**，一个端口都不用开：
>   ```bash
>   # 在你自己的电脑上执行
>   ssh -L 8000:127.0.0.1:8000 -L 5173:127.0.0.1:5173 root@120.26.22.166
>   # 然后本地浏览器直接开 http://127.0.0.1:5173 —— 体验和本地开发一模一样
>   ```

### 7.3 确认没有别的防火墙

Ubuntu 上如果开了 ufw，也要放行：

```bash
ufw status                       # 若 active
ufw allow 8000/tcp
```

## 8. 前端怎么上云（云上没 Node）

### 方案 A：在云上装 Node，开发模式跑（最快看到效果）

```bash
FRONTEND=1 bash scripts/setup_cloud.sh     # 装 Node 20 + npm install + build
cd /opt/rag-agent/app/frontend
npm run dev -- --host 0.0.0.0 --port 5173
```

> **注意 `--host 0.0.0.0`**：项目里 `vite.config.js` 写的是 `host: "127.0.0.1"`，
> 不加这个参数**外部访问不到**（这是很多人卡住的点）。
>
> 好处：Vite 的 dev proxy 是**在服务器内部**把 `/api` 转发到 `127.0.0.1:8000` 的，
> 所以浏览器只需要访问 `5173` 一个端口，**8000 都不用开安全组**。

### 方案 B：本地 build，把 `dist/` 传上去 + nginx（正式做法）

```bash
# 本地
cd frontend && npm run build
scp -r dist root@120.26.22.166:/opt/rag-agent/app/frontend/
```

nginx 配置（`/etc/nginx/sites-available/rag-agent`）：

```nginx
server {
    listen 80;
    server_name 你的域名或公网IP;

    # 前端静态文件
    root /opt/rag-agent/app/frontend/dist;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;   # SPA 路由回退（React Router 必需）
    }

    # 后端 API 反代（这样 8000 端口不用对外暴露）
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 600s;            # 入库任务可能跑几分钟
    }
}
```

```bash
ln -s /etc/nginx/sites-available/rag-agent /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

> `try_files ... /index.html` 别漏——前端的 `/knowledge`、`/chat` 等路由是前端接管的，
> 少了这一行刷新页面会 404。

## 10. ⚠ 一个隐性陷阱：`BASE_DIR` 会自动变成 `/opt/rag-agent`

`core/config.py` 里的推断链：

```python
if os.getenv("RAG_BASE_DIR"):
    BASE_DIR = os.environ["RAG_BASE_DIR"]
elif os.path.isdir("/opt/rag-agent"):     # ★ 云上会命中这一条
    BASE_DIR = "/opt/rag-agent"
else:
    BASE_DIR = <仓库根>
```

**后果**：在云上你把代码 clone 到**任何地方**（比如 `/root/我的项目`），
`CORPUS_DIR` / `MILVUS_PATH` / `MODEL_ROOT` **仍然指向 `/opt/rag-agent/...`**——
也就是说，它会用**旧部署的数据和模型**，而不是你新 clone 目录里的。

**这算特性还是坑？**
- 如果你就是想让新代码复用 `/opt/rag-agent` 的数据（**推荐做法**）——这是特性，正好省事。
- 如果你想跑一个完全独立的实例——**必须显式设** `RAG_BASE_DIR`：

```bash
export RAG_BASE_DIR=/root/我的项目
# 或在 .env 里写 RAG_BASE_DIR=/root/我的项目
```

**排错时先看这个**：

```bash
cd <代码目录> && /opt/rag-agent/venv/bin/python -c \
  "import sys;sys.path.insert(0,'.');from core import config;print(config.summary())"
# 输出里 CORPUS_DIR / MILVUS_PATH / Embedding 的路径是谁的，就一目了然
```

## 13. 安全清单（云上尤其注意）

1. **安全组别开 `0.0.0.0/0`**：这个服务**没有鉴权**，开放等于公开你的知识库 + LLM 配额。
2. **优先用 SSH 端口转发**（§7.2）做临时访问，一个端口都不用开。
3. **别把云上 PG 改成监听 `0.0.0.0`**：现在 `127.0.0.1` 是**正确且安全**的，本地开发靠 SSH 隧道就行。
4. **`.env` 权限 600**，且永远不要提交进 git（`.gitignore` 已挡）。
5. **OpenAI/DashScope key 轮换**：如果这个 key 曾经进过 git 历史或被贴进过日志，去控制台换一个。
6. **CORS**：`scripts/api.py` 现在是 `allow_origins=["*"]`（开发方便）。若域名/公网 IP 可达，
   建议收敛成白名单。
