# 阶段 5：Agent 自愈（Self-Healing）

> 目标：让系统**检测到自己答错了就自动重试**，而不是等人翻日志发现。
> 这是项目名 "Self-Evolving（自进化）" 第一个真正落地的形态。
>
> ```
> 生成答案 → 检测到「拒答」？ → 召回分够高？（说明资料里有答案，是模型没敢答）
>                                    ↓ 是
>                          判定「误拒」→ 换宽松指令 + 扩大召回 → 重试一次 → 采纳新答案
>                                    ↓ 否
>                              保持拒答（真的是没有答案）
> ```

---

## 一、为什么做自愈（这不是拍脑袋加的，是阶段 4 评估逼出来的）

阶段 4 做完混合检索后，A/B 数字是这样的：

| 指标 | vector 基线 | hybrid（阶段4）|
|---|---|---|
| 正确率 | 76.0% | 76.0%（**没提升**）|
| recall@1 / @3 | 66% / 74% | 66% / 74%（**完全没变**）|

召回率一动不动，说明**检索不是瓶颈**。那瓶颈在哪？翻逐题明细：

```
[错误] #42 FastAPI 应用返回数据无效（例如缺少字段）时会发生什么
       recall_top3=✓          ← 正确文档明明被召回到了！
       理由: 待评审回答直接表示无法回答，完全未覆盖参考答案核心要点
```

**召回是中的，但模型选择了拒答。** 也就是说：阶段 2 那句抗幻觉指令
「如果上下文里找不到答案，就说不知道」被**过度触发**了（over-refusal）——
上下文其实有答案，模型却判成"资料不足"。

所以阶段 5 的方向不是继续加召回（那已经被证明无效），
而是**修生成侧的过度拒答，并让系统自己完成这件事**。

> 这就是「先测量再优化」的价值：阶段 3 的评估不仅告诉我们"有没有提升"，
> 还告诉我们"下一步该改哪里"。否则我们会在检索上继续加码，白烧算力。

---

## 二、自愈策略：两步判定 + 两步动作

代码在 `core/self_heal.py`。

### 判定（两个条件同时满足才触发）

| 条件 | 怎么判 | 为什么 |
|---|---|---|
| ① 模型在拒答 | `is_refusal()`：答案里出现「无法回答/没有提供/不知道…」，空答案也算 | 这是系统**自己的失败信号** |
| ② 召回质量不差 | top1 余弦相似度 ≥ `0.5` | 说明资料里大概率有答案，是模型没敢答 |

### 动作（触发后做两件事，只重试一次）

1. **扩大召回**：`top_k × 2`（5 → 10），给模型更多素材
2. **换宽松指令**：用 `RELAXED_SYSTEM_PROMPT` 替代 `SYSTEM_PROMPT`

```python
# SYSTEM_PROMPT（严格，阶段2）
"如果【上下文】里找不到答案，请明确回答「根据提供的资料无法回答该问题」"

# RELAXED_SYSTEM_PROMPT（宽松，阶段5 自愈时用）
"请**先尝试**依据上下文作答，哪怕只能给出部分信息也要说出来，不要轻易说「无法回答」"
"只有当上下文与问题**完全无关**时，才说明「资料中未涉及该内容」"
```

### 校验：不自欺欺人

重试后的新答案**只有在不再拒答时才会被采纳**；如果重试后还是拒答，
就保持原答案 —— 不会为了让数字好看而强行替换。自愈失败也不会影响主流程。

---

## 三、为什么必须设阈值（最重要的设计）

评测集里有 **8 道 `unanswerable`**（语料里真的没答案），模型拒答是**正确行为**。

如果不加区分地「见拒答就重试」，就会把这 8 题也强行逼出答案 → **幻觉率飙升**，
阶段 3 辛苦测出来的 100% 拒答正确率会直接崩掉。

所以 `should_heal()` 的第二个条件（召回分 ≥ 0.5）是**安全阀**：

| 情况 | top1 相似度 | 判定 | 处理 |
|---|---|---|---|
| 拒答，但召回到相关内容 | 0.75 | 误拒 | **自愈重试** ✅ |
| 拒答，确实没召回（unanswerable）| 0.30 | 真没答案 | **不救**，保持拒答 ✅ |
| 正常作答 | 0.90 | 没问题 | 不触发 |

> 阈值 0.5 的依据：阶段 1 数据里，正确命中通常 0.70+，边缘 0.55~0.65，噪声 < 0.5。

### 用法

```bash
# 交互式问答 + 自愈
python scripts/ask.py "FastAPI 怎么做依赖注入" --self-heal

# 评估 + 自愈（和基线 run 3 直接可比）
python scripts/evaluate.py --self-heal

# 自愈 + 混合检索一起开
python scripts/evaluate.py --retrieval hybrid --self-heal
```

## 五、A/B 结果（真实数字）

> 环境同阶段 4：50 题、同一裁判、vector 召回（与基线 run 3 唯一差别就是开了自愈）。

| 指标 | 基线 run3（无自愈）| 自愈 run5 | 变化 |
|---|---|---|---|
| 题数 | 50 | 50 | — |
| **正确率**（裁判=2）| 76.0%（38/50）| **82.0%（41/50）**| **+6.0pp ✅** |
| 部分正确率 | 12.0% | 12.0% | ±0.0pp |
| **拒答正确率** | 100.0% | **100.0%** | **±0.0pp ✅** |
| recall@1 | 66.0% | 66.0% | ±0.0pp（符合预期：检索没动）|
| recall@3 | 74.0% | 74.0% | ±0.0pp |
| 耗时/题 | 15.16s | 18.13s | +2.97s（重试的代价）|

### 逐题变化

| 题号 | 基线 → 自愈 | 说明 |
|---|---|---|
| **#42** | 0 → **2** | **正是阶段 4 定位出的那道 over-refusal 题**，被成功救回 ✅ |
| #3 | 0 → **2** | 同样是被误拒，救回 ✅ |
| #19 | 0 → **2** | 救回 ✅ |
| #10 | 0 → 1 | 从"完全错误"提升到"部分正确" ✅ |
| #35 | 1 → 0 | ⚠️ **回退**：见下方分析 |

### 结论 1：自愈有效，且是数据驱动定位出来的

正确率 **76% → 82%（+6pp）**，是本项目到目前为止**唯一一次实打实的准确率提升**
（对比：阶段 4 的混合检索是 +0pp）。而且这次提升不是拍脑袋试出来的 ——
是阶段 4 的评估反向定位出"瓶颈在 over-refusal"，阶段 5 才针对性解决。

### 结论 2：阈值安全阀守住了拒答率（最关键）

**拒答正确率 100% → 100%，一道 unanswerable 都没被"救"成幻觉。**
这验证了第三节那个阈值设计的必要性：如果见拒答就重试，
8 道 unanswerable 会被强行逼出答案，正确率涨了但系统变得满嘴跑火车 —— 那是假提升。

### 结论 3：代价与回退（诚实记录）

- **耗时 +2.97s/题**：被救回的题要多调一次 LLM（扩大召回 + 重新生成）。
- **#35 回退（1 → 0）**：这题原答案是"部分正确"，但里面含有拒答措辞，
  于是触发了自愈；重试后的新答案不再拒答（所以被采纳），但裁判认为它更差。
  **暴露的改进点**：目前只在"新答案不再拒答"时就采纳，没有判断"新答案是否更好"。
  下一步可以加一道"新旧答案对比"裁判（代价是多一次 LLM 调用），
  或者只在旧答案是**纯拒答**（不含任何有效信息）时才自愈。

## 六、踩过的坑

1. **用关键词判拒答，而不是再调一次 LLM** —— 一次全量评估已经要调 100 次 LLM
   （50 题 × 生成+裁判），再加一层"判断是否拒答"会翻倍耗时和 token。
   关键词匹配虽然粗暴，但对「无法回答/没有提供/不知道」这类固定句式足够准。
2. **只重试一次** —— 自愈是为了救"误拒"，不是无限重试。多次重试会指数级烧 token，
   而且第二次还答不上来，基本说明是真的答不了。
3. **必须设召回分阈值** —— 见第三节。这是"自愈"和"制造幻觉"的分界线，
   也是保护 8 道 unanswerable 题拒答正确率的关键。
4. **自愈后指标要按"最终那次召回"算** —— 自愈会重新检索（top_k 翻倍），
   所以 `recall_top1/top3` 要用重试后的 `retrieved`，否则指标和输入对不上。
5. **重试后仍拒答就保持原样** —— 不自欺欺人，也不为了让数字好看强行替换。

## 七、与阶段 3/4 的因果链（这才是"自进化"的完整故事）

```
阶段 3  建立测量        → 能算出「正确率 76% / 拒答率 100%」
   ↓
阶段 4  尝试优化检索    → 混合检索后准确率没动、recall 没动
   ↓                      → 结论：检索不是瓶颈
阶段 4  评估反向定位    → 真正瓶颈是 over-refusal（召回中了却拒答）
   ↓
阶段 5  针对性自愈      → 让系统自己检测误拒并重试
   ↓
阶段 5  再测量          → 用同一套评估验证提升（本节 A/B）
```

**没有阶段 3 的评估，阶段 4/5 全是盲调** —— 这正是 "Self-Evolving" 里
"Evolving" 的含义：每一轮改动都由数据驱动，而不是由直觉驱动。

## 八、下一步（阶段 6 前瞻）

- **Rerank 精排**：现在自愈是靠"扩大 top_k"给更多素材，比较粗暴；
  上 rerank 后可以直接把最相关的块顶到最前，可能比扩大召回更精准。
- **自适应阈值**：现在 `0.5` 是拍的，可以用 `eval_result` 的历史数据反推最优阈值。
- **更多自愈信号**：不止"拒答"，还可以检测"答案太短""judge 给了 0 分""召回分低于均值"等，
  每种信号配一种重试策略 —— 这才是完整的 Self-Evolving Agent。
